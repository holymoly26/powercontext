# 验证样例

## 一、任务描述

> 为待办工具的 `list` 命令增加**按优先级筛选**能力。修改后：
> `list --priority 1` 只列出优先级为 1 的待办，其余待办不得出现；
> 不传 `--priority` 时行为保持不变。

## 二、有效规格（上下文中必须包含）

| 类型 | 来源 | 说明 |
|---|---|---|
| 规格 | `docs/spec.md#L14`（`section:SPEC-3 按优先级筛选（待实现）`） | 本次任务的直接依据 |
| 规格 | `docs/spec.md#L8`（`section:SPEC-2 列出全部待办`） | 既有行为，不得破坏 |
| 规格 | `docs/spec.md#L30`（`section:SPEC-5 兼容性约束`） | 兼容性要求 |
| 代码 | `todo.py#L44`（`function:list_items`） | 需要修改的函数 |
| 代码 | `todo.py#L63`（`function:main`） | CLI 调用入口 |
| 测试 | `tests/test_todo.py#L50`（`test_filter_by_priority`） | **目标测试** |
| 测试 | `tests/test_todo.py#L54`（`test_filter_returns_only_matching`） | **目标测试** |
| 测试 | `tests/test_todo.py#L33`（`test_list_all`） | 回归测试 |

> 规格更新并重新导入后，`version` 递增、检索结果随 `content` 变化（实测 `3→4`），
> 说明上下文不是硬编码。

## 三、初始数据

- seekdb 库 `sdd`，表 `context_docs`，共 **19 条**：`code` 6 条 / `spec` 6 条 / `test` 7 条
- `biz/todo.py` 处于**修改前**状态（`list_items` 直接 `return load_items()`）
- 两个目标测试此时**失败**

## 四、操作步骤

```bash
# 0. 依赖
python -m pip install -r requirements.txt
python -m pip install "powercontext[cli,server]" jsonschema

# 1. 建表 + 导入工程资料（一条命令，不需要 mysql 客户端）
python ctx/importer.py --root biz --reset --init-db
# 期望：schema applied: 3 statements / table truncated / imported 19 documents from biz

# 2. 查询上下文
python ctx/query.py --task "为 list 命令增加按优先级筛选"
# 期望：specs 含 docs/spec.md#L14；code 含 todo.py#L44；tests 含 test_filter_by_priority

# 4. 修改前测试（关键：必须因功能缺失而失败）
python -m unittest discover -s biz/tests -v
# 期望：FAILED (failures=2)，且失败原因是 AssertionError

# 5. 让 MiniMax 完成修改
python ctx/minimax_client.py --task "为 list 命令增加按优先级筛选" --apply
# 期望：HTTP 200，base_resp.status_code=0，日志追加到 logs/minimax_session.md

# 6. 修改后测试
python -m unittest discover -s biz/tests -v
# 期望：Ran 5 tests ... OK，exit=0

# 7. 任务状态写入 PowerContext
powercontext server run          # 另开终端
python ctx/state.py done "用 MiniMax 完成 list_items 的 priority 筛选改造"
python ctx/state.py verify "目标测试由 2 FAIL 转为 5/5 OK"

# 8. 重启后复用
#    关掉 PowerContext 服务再启动，然后：
python ctx/state.py show
# 期望：done / todo / verifications 三类内容仍在，backend=powercontext
```

## 五、预期结果

| 步骤 | 预期 |
|---|---|
| 导入 | 19 条文档，符号唯一 |
| 查询 | 输出 JSON，`source` 形如 `docs/spec.md#L14`，可在仓库中定位 |
| 修改前测试 | `FAILED (failures=2)`，失败项为目标测试 |
| MiniMax 调用 | `HTTP 200`，`base_resp.status_code = 0` |
| 修改后差异 | 仅 `list_items` 函数变化（见 `logs/patch.diff`） |
| 修改后测试 | `Ran 5 tests ... OK` |
| 状态复用 | 服务重启后 `state` 仍可读，并出现在 `query.py` 的 `state` 字段 |

## 六、重置方法

```bash
# 1. 恢复源码到修改前
cp logs/todo.py.before biz/todo.py

# 2. 清空并重新导入数据库
python ctx/importer.py --root biz --reset

# 3. 清空本地状态与日志（PowerContext 侧状态可新建 scope 隔离）
rm -f ctx/state.json .pc_scope logs/minimax_session.md logs/patch.diff

# 4. 需要时重启 PowerContext 服务
```
