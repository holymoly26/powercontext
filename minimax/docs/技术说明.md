# 一页技术说明

## 1. 模块结构

```
minimax/
├─ biz/                     被改造的业务工程（待办 CLI + pytest/unittest 测试）
│  ├─ todo.py               list_items 为本次修改点
│  ├─ docs/spec.md          规格 SPEC-1 ~ SPEC-5
│  └─ tests/test_todo.py    3 个回归测试 + 2 个目标测试
├─ ctx/                     上下文模块
│  ├─ importer.py           切块入库：Markdown 按二级标题、Python 按函数/方法
│  ├─ query.py              按任务检索 → 输出 JSON 上下文（CLI 入口）
│  ├─ db.py                 seekdb / OceanBase 连接（MySQL 协议，2881）
│  ├─ state.py              任务状态读写（双后端：PowerContext / 本地文件）
│  ├─ pc_state.py           PowerContext HTTP 客户端
│  └─ minimax_client.py     组装 prompt → 调 MiniMax → 提取代码 → 写回源码 → 记日志
├─ logs/                    全部证据（差异、前后测试、MiniMax 会话、PC 调用记录）
└─ schema.sql               seekdb 建表语句
```

**调用入口**：`python ctx/query.py --task "<任务>"`（CLI）。

**输入**：一句任务描述。
**输出**：JSON，含 `specs` / `code` / `tests`（每项带 `source: 路径#行号`）与 `state`（done/todo/verifications）。

## 2. 上下文是怎么选出来的

1. **入库**：`importer.py` 遍历 `biz/`，按文件类型切块——
   Markdown 按 `## ` 切（每节一条），Python 用 `ast` 按函数/方法切（`function:Class.method` 作唯一符号）。
   每块记录 `path / symbol / kind / title / content / lineno`，写入 `context_docs` 表。
   **行号真实可回溯**，`source` 直接映射到仓库中的位置。

2. **检索**：`query.py` 把任务描述分词（英文按单词、中文按 2 字滑窗），
   对每条文档的 `title + path + content` 做词频计分，按分数排序后分 `spec/code/test` 三桶各取前若干条。

3. **为什么不是硬编码**：检索结果**完全来自数据库实时查询**。
   把 `spec.md` 的某一节改动后重新 `import`，该行 `version` 递增、`content` 更新，
   下一次检索就返回新内容（实测 `version 3→4`、新文本首现位置 `0→30`）。
   检索逻辑不针对任何具体任务写死。

## 3. 三项技术的分工

| 技术 | 承担的作用 | 实现方式 | 证据 |
|---|---|---|---|
| **MiniMax** | 依据上下文生成代码修改 | `POST /v1/text/chatcompletion_v2`（OpenAI 兼容），模型 `MiniMax-Text-01` | `logs/minimax_session.md`（含任务、上下文来源、prompt、原始返回、提取代码），与 `logs/patch.diff` 一一对应 |
| **seekdb / OceanBase** | 存储工程资料，检索结果用于构造上下文 | 库 `sdd`、表 `context_docs`（InnoDB, utf8mb4），19 条记录；`query.py` 的每条 `source` 都来自该表 | `schema.sql`、`logs/patch.diff` 同源；检索输出带真实行号 |
| **PowerContext** | 保存任务进展与验证结果，重启后读取复用 | `powercontext 1.4.1`，HTTP API：`/v1/scopes` 建 Scope、`/v1/memory/remember` 写入、`/v1/memory/search` 还原 | `logs/powercontext.log`；服务重启后 `state.py show` 仍返回三类状态并注入 `query.py` 的 `state` 字段 |

三者串成一条闭环：

```
seekdb(资料) ──检索──▶ 上下文 ──prompt──▶ MiniMax ──代码──▶ 业务工程 ──测试──▶ 结果
                                                  │
                                                  └──状态写入──▶ PowerContext ──重启后读回──▶ 下一轮上下文
```

## 4. 异常与降级

- PowerContext 不可用时，`state.py` 自动回退本地 JSON（`STATE_BACKEND=file` 可强制）。
- MiniMax 返回内容未按代码块格式时，`minimax_client.py` 用正则提取；提取结果先 `ast.parse`
  校验语法，不合法**不会写回源码**，避免破坏业务工程。
- 数据库连接参数全部走环境变量（`SEEKDB_HOST/PORT/USER/PASSWORD/DB`），默认 `127.0.0.1:2881`。

## 5. 已知限制

- 检索为**词频匹配**，非语义检索；同义改写可能降低命中率。
- 切块粒度是「函数/小节」，超长函数不会被进一步拆分。
- 未在 Windows 之外验证（PowerContext 官方标注 Windows 为 experimental，实测 1.4.1 可运行）。
